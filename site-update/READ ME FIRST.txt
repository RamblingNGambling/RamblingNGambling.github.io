SGA 20+ ON THE LIVE SITE: WHAT TO DO
====================================

Why the page was missing
------------------------
The live site is not made from the pages that Bet Desk publishes. A script in
the site repository (the "build" folder) makes the site every time plays.json
changes. That script only knew plays.json, so it had no SGA page.

The files in this folder teach it about the SGA experiment. Nothing here has
been sent to GitHub. You send it, in the steps below.

What changes on the site
------------------------
- A new page: /sga/ (the roll, the ladder chart, every game, the bet slips).
- A new "SGA 20+" link in the top menu.
- A small line under the ticker on the home page that points to it.
- Nothing else. With no SGA data, every other page comes out exactly as before.
- If the SGA data is ever wrong or missing, the page is simply skipped and the
  rest of the site still updates.

Steps
-----
1. In Bet Desk: reload the page, then press Publish once.
   This adds a new file, sga.json, next to plays.json.
   (The SGA switch on the SGA 20+ tab must be ticked, and at least one game logged.)

2. On GitHub, open the site repository, branch "main".
   (RamblingNGambling / RamblingNGambling.github.io)

3. Click  Add file  >  Upload files.

4. Open this folder (site-update) on your computer and drag the folder called
   "build" onto the GitHub page. It holds 7 files. GitHub keeps the folder
   names, so the files land in the right places and replace the old ones.

5. Under the files, type a short message such as  Add SGA 20+ page  and press
   Commit changes (keep "Commit directly to the main branch").

6. Wait about two minutes. Open the Actions tab on GitHub: you will see
   "Rebuild site from plays.json" run, then "pages build and deployment".
   Both should end with a green tick.

7. Open  ramblingngambling.github.io/sga/

Steps 1 and 4 can be done in either order. The page appears once both are done.

If a step goes wrong
--------------------
- The site stays as it was until a build finishes with a green tick. A failed
  build changes nothing on the live site.
- To switch the page off later: untick "Show the SGA 20+ rollover" in Bet Desk and
  Publish. The page, the menu link and the home line all disappear.

Two things to know
------------------
1. YOUR FIRST SLIP SHOWS THE DOLLAR AMOUNTS.
   The screenshot you published (Oct 25, vs LAC) shows "Wager: $30.00" and
   "Payout: $34.50". Bet Desk blurs dollar amounts unless the "Blur dollar amounts"
   box is cleared when the screenshot is saved, and that box was cleared for this one.
   If you want them hidden: in Bet Desk open the SGA 20+ tab, press "slip" on that
   game, drop the screenshot in again with the box ticked, press Save changes, then
   Publish. The old picture stays in the repository's history (it cannot be removed
   without rewriting history), but it will no longer be on the site.
   If you want the amounts visible, nothing needs to change. The page then stops
   saying that the first stake is not shown.

2. KEEP THE OTHER COPY OF THE BUILD FOLDER IN STEP.
   The build folder was made in another workspace on your machine (its README
   mentions "../site" and ship.sh). If you keep a copy there, apply
   sga-page.patch to it (git apply sga-page.patch) or copy these 7 files over it.
   Otherwise the next "sh ship.sh" from that copy will take the SGA page out again.

Files in this folder
--------------------
build/build.mjs               the site builder (adds the SGA page; 224 new lines)
build/src/sga.js              new: the ladder chart and the slip viewer
build/src/site.css            the design rules (SGA rules added at the end, nothing changed)
build/verify/check-sga.mjs    new: 20 checks on the SGA page, including bad and hostile data
build/verify/check-pages.py   the page checker now includes /sga/ when it exists
build/ship.sh                 now also runs check-sga.mjs
build/README.md               notes on the new optional page
sga-page.patch                all of the above as one patch, for the other copy
